# 🚀 주문 체결 확인 시스템 가이드

## 📋 개요

기존 시스템의 문제점인 "주문 접수 ≠ 주문 체결" 문제를 해결하기 위해 새로운 주문 체결 확인 시스템을 구축했습니다.

## ❌ 기존 문제점

1. **잘못된 알림**: 주문이 접수만 되었는데 "매도 완료"라고 알림
2. **실제 거래 상태 불일치**: 사용자가 실제 체결 여부를 알 수 없음
3. **손절 실패 시 잘못된 정보**: 매도가 실패했는데도 성공으로 표시

## ✅ 해결 방안

### 1. **주문 상태 구분**
- `PENDING`: 주문 접수 (기존의 "success: true")
- `EXECUTED`: 체결 완료 (실제 거래 성공)
- `PARTIAL`: 부분 체결
- `FAILED`: 주문 실패/거부
- `TIMEOUT`: 체결 확인 시간 초과

### 2. **새로운 함수들**

#### `executeOrderWithConfirmation()`
```dart
// 기존: 주문 접수만 확인
final result = await kisApi.executeOrder(...);

// 새로운: 주문 실행 + 체결 확인
final result = await kisApi.executeOrderWithConfirmation(
  stockCode: '005930',
  orderType: 'SELL',
  quantity: 100,
  price: 75000.0,
  confirmationTimeout: Duration(minutes: 5),
);
```

#### `checkOrderExecution()`
```dart
// 주문 체결 상태 실시간 확인
final executionStatus = await kisApi.checkOrderExecution(
  orderId,
  timeout: Duration(minutes: 5),
  checkInterval: Duration(seconds: 10),
);
```

## 🔄 사용법

### 1. **기본 주문 (체결 확인 포함)**
```dart
// 자동으로 체결 상태까지 확인
final result = await kisApi.executeOrderWithConfirmation(
  stockCode: stockCode,
  orderType: 'SELL',
  quantity: quantity,
  price: price,
);

// 결과 확인
switch (result['orderStatus']) {
  case 'EXECUTED':
    print('🎉 체결 완료: ${result['executedQuantity']}주');
    break;
  case 'PARTIAL':
    print('⚠️ 부분 체결: ${result['executedQuantity']}주');
    break;
  case 'FAILED':
    print('❌ 주문 실패: ${result['message']}');
    break;
  case 'TIMEOUT':
    print('⏰ 체결 확인 시간 초과');
    break;
}
```

### 2. **수동 체결 확인**
```dart
// 주문 후 별도로 체결 상태 확인
final orderResult = await kisApi.executeOrder(...);
if (orderResult['success'] == true) {
  final executionResult = await kisApi.checkOrderExecution(
    orderResult['orderNo'],
    timeout: Duration(minutes: 5),
  );
  // 체결 결과 처리
}
```

## 📊 상태별 처리 로직

| 상태 | 의미 | 처리 방법 |
|------|------|-----------|
| `EXECUTED` | 체결 완료 | ✅ 성공 처리, 거래 내역 업데이트 |
| `PARTIAL` | 부분 체결 | ⚠️ 부분 성공, 남은 수량 재주문 고려 |
| `FAILED` | 주문 실패 | ❌ 실패 처리, 재시도 로직 실행 |
| `TIMEOUT` | 확인 시간 초과 | ⏰ 수동 확인 필요, 알림 발송 |
